## /feed — user discovery feed (frontend, match data only)

Build the `/feed` route where users discover other users ordered by compatibility, plus a detail page per user. Uses only the **existing** backend matches API — no backend changes.

### Route structure
- **`/feed`** — scrollable feed of match cards (compatibility score, highest first)
- **`/feed/[id]`** — a single matched user's profile detail (match score, breakdown, shared highlights, discord handle)
- **Rename** the existing `app/(app)/matches/` → `app/(app)/feed/` (both `page.tsx` and `[userId]/page.tsx` → `[id]/page.tsx`)
- Update the `/home` quick link from `/matches` → `/feed`, title "Matches" → "Feed"
- Update docs

### Data layer (`lib/api/matches.ts` + types)
Replace the `getMatches()` / `getMatch()` stubs with real implementations:
- `getMatches(cursor?: string, limit = 20)` → `GET /matches?limit=&cursor=` returning `{ items: Match[], next_cursor }` (types already exist in `types/api.ts`: `Match`, `MatchListResponse`)
- `getMatch(userId)` → `GET /matches/{userId}` returning `Match`
- Wire up `POST /me/recompute` in `lib/api/embeddings.ts` (currently a stub) → `recomputeMatches()` server action in `lib/actions/match-actions.ts`

### New reusable components (`components/matches/*` + `components/ui/avatar.tsx`)
All currently stubs — build them out:
1. **`Avatar`** (`components/ui/avatar.tsx`) — real reusable component: `rounded-full` + `<img object-cover>` + `UserRound` fallback (from the profile-form pattern), sized via a `size` prop. Server component. Used by both feed cards and detail.
2. **`MatchCard`** (`components/matches/match-card.tsx`) — one card in the feed: avatar, display name, bio (truncated), compatibility score badge, shared-highlight chips, matching-mode tag. Links to `/feed/[id]`.
3. **`MatchScore`** (`components/matches/match-score.tsx`) — reusable compatibility score display (percentage + colored ring/bar). Used on both card and detail.
4. **`MatchHighlights`** (`components/matches/match-highlights.tsx`) — shared highlights as chips with service brand icons. Reused on card (compact) and detail (full).
5. **`MatchList`** (`components/matches/match-list.tsx`) — client component wrapping the infinite-scroll/“Load more” behavior: fetches initial page server-side, loads subsequent pages client-side via cursor, shows loading/empty states.
6. **`MatchDetail`** (`components/matches/match-detail.tsx`) — the full profile view: avatar, name, bio, score, per-service breakdown bars, shared highlights, discord handle reveal, back-link to /feed.

### Pages
- **`/feed` (`app/(app)/feed/page.tsx`)** — Server Component. Auth gate (401→/login). Fetches first page of matches server-side via `getMatches()`, passes to `<MatchList>`. Header via `PageHeader` (icon: Users/Compass, title "Feed", description). Includes a "Refresh matches" action (calls recompute server action, rate-limited 1/hr server-side). Empty state when not matchable or no matches.
- **`/feed/[id]` (`app/(app)/feed/[id]/page.tsx`)** — Server Component. Auth gate. Fetches `getMatch(id)`. Renders `<MatchDetail>`. 404 handling if no match row exists. Header shows back-link to /feed.

### Edge cases handled
- **Cache miss:** first `/matches` call after expiry returns empty + triggers backend refresh → show a "Loading matches…" state with auto-poll (the feed client component re-fetches after a short delay).
- **Not matchable:** `is_matchable=false` → 403 from backend → show a CTA to enable matching (links to `/settings/privacy`).
- **Rate limit:** recompute is 1/hr → disable button + show remaining time after a recompute.
- **Empty bio/highlights:** graceful omission, no broken layout.
